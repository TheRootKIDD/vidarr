Model sizes are fixed by `docs/06 §3` (ADR-015, ADR-018): `screen` and `small` are matched to a 12-layer, $d$ = 768 dense model (≈ 0.6 GFLOP/token training cost); the recurrent default is single-stream, $r$ = 8, $N_e$ = 8, $k$ = 2 (≈ 80 M total params), with the parameter-matched $N_e$ = 128, $k$ = 4 variant (≈ 250 M total) for H6; `medium` is matched to a 24-layer, $d$ = 1024 dense model (≈ 2 GFLOP/token; $r$ = 16; ≈ 160 M / ≈ 700 M total). Token budgets 1 B / 2.5 B / 7 B (§7). `screen` runs every variant once; `small` runs the decisive steps (L0, L1, L2, **L3**, L5, L5d, ~~L6~~ (closed at `screen`, ADR-046), ~~L7~~ (closed at `screen`, ADR-048), L9) at 2 seeds, plus **L5-ne128, L7b, L5-pm, L3b, L8b** (ADR-058) and any L5-family arm that beats L5 by > 4σ at `screen` (ADR-031). L3 was added by ADR-030, because H13's own prior (I20) says 1 B tokens is too small a budget to interpret an MTP failure at; `medium` confirms L0, L1 and the two best recurrent variants. L8 splits into L8 (GPU product-key memory over sentence embeddings, parametric values, in-loop), L8b (chunk-level external retrieval, neighbours precomputed offline), L8q (L8 plus a query-side retrieval loss distilled from the frozen encoder on the preceding chunk, ADR-055), L8k (L8q with fixed PCA sub-keys scored by distance, ADR-056), L8c (encoder fine-tuned by backpropagation, budget permitting) and L8d (entailments instead of sentences, only if L8 is used) — `docs/06 §5`, ADR-009.

**Recurrence caveat.** Shared-block benefits (H6) may only appear with scale; if `small` is silent on H6, that is a recorded outcome, not a failure — fit across three sizes if the budget allows.

**How an Embla idea transfers.** Embla minimises bytes read per token at batch 1; the note's units are compute-bound at $Z \approx N_e b_{min}/k$ tokens in flight. *Batching test*: a saving from skipping **weights** (dead expert neurons) vanishes once a batch unions the rows it needs ($1 - (1-p)^b$ of the rows are read, S12). A saving from skipping **KV** (zero attention weights, selection reuse, bridges) survives, because each decode token reads only its own sequence's cache. *Recurrence test*: Embla's layer is our iteration, a block of four layers is a group of iterations, and "the preceding full layer" is the last full iteration.

**L5d-nope — positional split** (H22). On L5d: RoPE on $q, k$ in the local range only; the global range carries no positional encoding. Variant: NoPE on both ranges (expected worse). Also report ANN recall@$K$ of an HNSW index over $\mathcal{G}$ keys, NoPE vs RoPE (Q9's motivation). Config `attention.rope_scope: all | local | none`. Cost 1 (+1). Precedents: Embla (RoPE only in window layers); Kazemnejad et al. 2023.

**L5h — bridged global cache, prefill early exit** (H20). On L5d: token $t$'s global entry is $K_t = W_K^b\,\mathrm{LN}(c_t^{(j_b)})$, $V_t = W_V^b\,\mathrm{LN}(c_t^{(j_b)})$, with $j_b$ ∈ {1, 2, 4, $r$} ($j_b$ = $r$ is L5d).
- The bridge pair is **separate parameters**, not the local range's $W_K, W_V$, which see a different iteration's inputs (trap 2).
- *Prefill*: prompt tokens run $j_b$ iterations, and the last $W$ prompt tokens run all $r$, because the first decode token needs their local per-iteration caches (trap 1). That is ≈ $L j_b + W r$ iterations instead of $L r$.
- *Training*: segment-recurrent as ADR-021; earlier segments' $\mathcal{G}$ comes from their $j_b$ states, with ADR-023's stop-gradient. *Decode*: unchanged (each token runs $r$ iterations; its $\mathcal{G}$ entry is written after iteration $j_b$).
- *Measure*: loss; needle/copy and long-document loss at 2 k–8 k; S5 TTFT, sequential vs bridged.
- *Prediction*: $j_b = r/2$ near-free; $j_b$ = 1 costs more on retrieval than on loss.
- With $j_b$ = 1 the segment-sequential critical path is one iteration per segment, which makes concrete the author's "less effective parallel prefill mode" (ADR-024 option b). E-Q12 compares it with local-only prefill.
- Config `attention.global_source: per_iteration | final_vector | bridged`, `attention.bridge_iteration: int`. Cost 3 ($j_b$ = 1, 2, 4).
- Precedents: YOCO; HySparse2; DeepSeek-V4.1-Flash's causal encoder-decoder (8 B active in prefill vs 16 B in decode); Embla's bridges (layer 20 reads layer 16's K/V input point, layers 24 and 28 read layer 7's, so only the last prompt token runs all 32 layers, ≈ 2× prefill).

**L9-relu2 — ReLU² global attention** (H23, H15b). On L5d-nope: global weight $w_s = \mathrm{relu}(\langle \hat q, \hat k_s\rangle)^2 / \sum_{s'} w_{s'}$ with RMS-normalised $\hat q, \hat k$; the local range keeps softmax. The normaliser can be zero, so the global branch must be able to contribute nothing without NaNs. That needs a two-branch combination, i.e. **ADR-008 amended for this variant** (trap 3).
- *Measure*: loss; zero fraction over training, per $j$ and per head; loss vs an eval-time cap $K$ ∈ {256, 1024, 4096} on the uncapped model; the V-skip rate (keys zero for every query head of a KV group).
- *Indexer consequence*: train the `01 §6.2` indexer as a classifier of "block holds a surviving key" against the model's own exact-zero support, instead of KL to a softmax teacher; compare recall and loss with the dense-teacher plan.
- With L5g, select by **pre-ReLU score**, not survival, so keys just below zero stay selectable (trap 4).
- Config `attention.global_scoring: softmax | relu2`. Cost 2 plus eval sweeps.
- Precedents: Embla (≈ 50.8 % zeros at initialisation, ≈ 95 % after training, no sparsity loss); So et al. 2021 (Primer, squared ReLU).

**E-router-EQB — Exact Quantile Balancing** (H26). Inside L5 at $N_e$ = 8 and 128. (a) ADR-004's bias update plus small auxiliary loss (L5 itself); (b) EQB **per iteration**: after every step each expert's selection bias is set to the exact cutoff that would have given it $k/N_e$ of that iteration's tokens; (c) EQB **per step**: the cutoff is taken over all (token, iteration) pairs of the step. Selection uses biased scores, gate weights the unbiased ones; cutoffs by exact selection over bf16 scores.
- *Measure*: loss; per-iteration histogram entropy; co-activation statistics for the placement controller.
- *Prediction*: (b) erases depth specialisation and costs loss; (c) matches or beats (a).
- Config `router.balance: aux_free | eqb_iteration | eqb_step`. Cost 4 runs (b, c at both $N_e$; the $N_e$ = 128 runs are ≈ 19 h each).
- Precedents: Neitemeier et al. 2026; Aleph Alpha Kolibri-1 (384 routed experts per layer, 6 active + 1 shared).

**L5g — global-attention schedule with selection reuse** (H21). On L5d or L5h: iterations are *full* (all of $\mathcal{G}$; ReLU² if L9-relu2 is on), *sparse* (the $K_{sel}$ keys scored highest by the last full iteration, plus the local window, own softmax) or *local* (window only). Schedules: all full (= L5d), `[F,S,S,S] × 2`, `[F,S,S,S,L,L,L,L]`, `[F,S,S,S,S,S,S,S]`.
- *Measure*: loss; long-context evals; global reads per token (counted), which feed S6. Add attention-side bytes and reads counters to `sim/`'s outputs (`02 §14`) before this or L9-relu2 runs (trap 9).
- Config `attention.schedule: list[str]`, `attention.k_sel: 1024`. Cost 3.
- Precedent: Embla's 5 full / 12 sparse / 15 window layers, each sparse layer reusing its block's full-layer cache restricted to the top 1,024 keys plus the 128 most recent.

**L8e — engram table** (H24, H17). On L5 (not on L8, which is closed). Hash the last-2 and last-3 token ids, with different seeds, into a table of 2²¹ rows × $d$; the two rows give an engram vector $e_t$, computed once per token before the middle block and exposed to every iteration, either as an additive branch with a zero-initialised output projection or as a source in L5f's mix (Embla uses the latter).
- *Size at `small`* ($d$ = 768): 2²¹ rows ≈ 1.6 B parameters, ≈ 3.2 GB bf16, ≈ 22 GB with fp32 master weights and Adam states (2²² doubles it, ≈ 45 GB): host RAM (128 GB), not VRAM.
- *Placement*: table and optimiser states in host RAM; ≈ 2 × $d$ × 2 B per token gathered, ≈ 1.6 GB per 0.5 M-token step; sparse gradient scatter and a CPU Adam update on touched rows. This measures the P16/P17 "table off-chip" claim for real; log gather and scatter time per step. A rig probe sizes it before the run. CPU work beside a DDP run costs it 3–12 %, so the probe is part of the design, not an afterthought.
- *Traps*: hash collisions are intended; hash across segment boundaries the same way in training and inference (trap 6). Pin the gathered rows, overlap the gather with the previous step's backward, and finish the CPU update before the next gather of the same rows, or allow one step of staleness and log it (trap 7).
- *Compare*: L8e vs L5 (held-out, wiki-lead); L8e + L8b-pv vs L8b-pv (ADR-065).
- Config `engram: { enabled, rows: 2097152, ngrams: [2, 3], placement: host | gpu }`. Cost 2 plus the probe.
- Precedents: DeepSeek's Engram (Cheng et al. 2026, `05 §P17`: 27 B parameters, iso-FLOPs gains); Qwen3.8-Next (51 B parameters of n-gram tables prefetched from host memory); Embla (3 B, SSD-resident).

**L5f — attention residuals over iterations** (H25). On L5: before attention and again before the MoE at iteration $j$, the input is a per-token softmax mix of {embedding, engram or memory read if present, outputs of iterations $1..j-1$, partial sum of the current iteration}, with one learned query per mix (two per block) plus $e_j$.
- *Measure*: loss; mix weights per $j$ (which iterations the deep ones read).
- Config `middle.input_mix: residual | attention_residual`. Cost 1–2.
- Precedents: Kimi Team 2026 (Attention Residuals); Embla's 8 blocks of 4 (≤ 10 sources per mix).

**L10b′ — late QAT** (H3). 4-bit weight fake-quant (round-to-nearest, groups of 64, bf16 scale and offset per group) in the last 2 % of steps, vs from step 0, vs post-training round-to-nearest, on L0 and L1. The late and post-training arms reuse the existing checkpoints' schedule (≈ 0.2 run each); the from-step-0 arm is a full `screen` run. Quality only. Precedents: Embla (QAT in the last 2,000 SFT steps, 4-bit); Jacob et al. 2018.

**S12** is in §3. **Order**: L5d-nope → L5h ($j_b$ sweep) → L9-relu2 → E-router-EQB → L5g → L8e → L5f → L10b′; S12 any time. `small` confirmations first for L5h and L9-relu2. Budget in `§5` Phase 3.

## 4. Metrics
- **Quality**: loss/perplexity at matched FLOPs and tokens; a fixed eval suite (knowledge-heavy, long-context retrieval and copy, code) — ADR-014.
- **Compute**: FLOPs/token for prefill and decode; total and per-iteration parameters; parameters resident per unit.
- **Systems**: fabric bytes/token/iteration per tier; latency per iteration and per token (p50/p99); tokens in flight; utilisation; cold hits/token; availability.
- Every `results.md` carries: H numbers touched, verdict (supports / weakens / silent), config hash, seeds, hardware, wall-clock, one-paragraph interpretation.

## 6. Risks and mitigations
| Risk | Mitigation |
|---|---|
| Recurrent shared block unstable at $r_{max}$ | Start $r_{max}$ = 8; norm modulation; per-iteration residual scale; MoEUT-style norm/grouping tricks |
| Router collapse or early-expert hot-spotting | Depth embedding; aux-free bias; per-$j$ histograms logged from L5 on |
| Compounded changes hide regressions | Ladder discipline; two baselines per step |
| Simulator not trusted | Calibrate against a published deployment before any S-result |
| Four 12 GB cards: `medium` ≈ 1 week per run, nothing larger | `screen` → `small` → `medium` gating (`06 §7`); `medium` for ≤ 5 runs; scaling statements marked provisional |
| Thin experts at matched FLOPs confound H4/H6 (worst in the $N_e$ = 128 and two-stream variants) | Author's local default is $N_e$ = 8 (Q6); trade $k$ or $r$ explicitly and log it; report $d_{ff}$ next to every loss |
| Per-iteration retrieval infeasible in training (CPU index QPS) | L8 = GPU product-key memory; L8b = chunk-level retrieval precomputed offline |
| No FP8/FP4 on Ampere | quality via fake-quant; speed claims to the cost model, labelled as such |
| Indexed attention hurts exact copy | Dense window $W$; needle/copy tasks in the eval suite |
| Final-vector-only global attention (v2) loses what intermediate iterations could have offered far tokens | L5d measures it before anything is built on it; fallback variant: global over the final vector plus one mid-iteration vector |
| Knowledge-pipeline noise | Start from a clean structured source; measure coverage separately from model quality |
| Drifting into building a production trainer | `model/` stays a reference implementation on PyTorch DDP/FSDP built-ins; no custom kernels, no cross-GPU expert parallelism in training code |
| Silent hardware faults (no ECC, thermal throttling) | Log loss spikes, gradient norms and `nvidia-smi` power/thermals per run; rerun before interpreting |
| Over-fitting the spec to one hardware vendor | `U`, $s_{min}$, $\phi$, $\beta_C$ are scenario inputs; at least two scenarios per S-experiment |

## 7. Compute and data assumptions
- **Hardware**: one workstation — Threadripper PRO 3945WX, 256 GB DDR4 (251.5 GiB; was 128 GB before `020`–`022`), 4 × RTX 3060 12 GB, no NVLink/P2P (`docs/06 §1`). Planning throughput 32 TFLOPS dense / 20 TFLOPS variants aggregate until measured.
- **Token budgets**: `screen` 1.0 B, `small` 2.5 B, `medium` 7 B tokens at context 2048. Wall-clock ≈ 8 h / 21 h / 8 d per variant run (`06 §4`). Whole programme ≈ 2 months of GPU time, 3–4 calendar months.
- **Pretraining corpus**: FineWeb-Edu `sample/10BT` (ODC-By), tokenised once to a `uint16` memmap on `/mnt/nvme/corpus`; tokenizer = Mistral-7B-v0.1 32 k (Apache 2.0); held-out = first 10 000 documents of shard 000 — ADR-014.
- **Knowledge source**: a Wikipedia sentence slice (e.g. article lead sentences) embedded with a pretrained sentence encoder into a 2²⁰–2²¹-entry product-key table for L8 (author's addendum: no entailment extraction); the same slice with offline-precomputed chunk neighbours for L8b; entailment-style atomic facts only for L8d.
- **Long-context evals**: synthetic needle/copy at 8 k–32 k, a RULER-style subset, long-document perplexity (PG-19 candidate), all at inference over the real VRAM/host/NVMe tiers. Note: with one $\mathcal{G}$ entry per token, 32 k of context is ≈ 33 MB per sequence at `small` — S6's tier limits must be set artificially small to exercise the warm/cold paths at our context lengths.
